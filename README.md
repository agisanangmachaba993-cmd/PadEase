# PadEase Website Project

PadEase is a menstrual health website created for the WEDE5020 Practical/POE. The website aims to provide affordable and accessible menstrual products while promoting menstrual health, education and confidence.

## Project Goals

The main goals of the PadEase website are:

- To provide information about affordable menstrual products.
- To make menstrual products more accessible.
- To promote menstrual health and hygiene.
- To provide users with information about the services offered by PadEase.
- To create a professional, user-friendly and attractive website.
- To support women and girls by providing useful menstrual health information.

The lightbox should be tested for correct image display, responsive behaviour and keyboard accessibility.

### 3.2 Dynamic Content and Service Search

The service page includes a search feature that allows users to search for services using keywords. This helps users locate relevant information more efficiently.

### 3.3 Service Sorting

### 3.4 Interactive Maps

## 4. Search Engine Optimisation (SEO)

SEO improvements are intended to help search engines understand the website's pages and content.

### 4.1 Title Tags

Each page should have a descriptive and relevant HTML title that identifies its content.

### 4.2 Meta Keywords

Meta keywords must be checked against the rubric. If implemented, relevant keywords should be included in the page metadata without unnecessary repetition.

### 4.3 Meta Descriptions

Page-specific meta descriptions have been added to the website pages to summarise their content.

### 4.4 Image File Names and Alternative Text

Image filenames should be descriptive, and images should include appropriate `alt` attributes. Alternative text should explain the meaningful content of each image.

### 4.5 Robots.txt and Sitemap.xml

The project includes a `robots.txt` file and a `sitemap.xml` file.

The `robots.txt` file provides instructions for search-engine crawlers. The sitemap lists the website pages that should be discoverable by search engines.

Before submission, replace any placeholder website address in `sitemap.xml` with the actual published website URL and verify that the sitemap references the correct pages.

## 5. Contact Form Functionality

The contact page includes a form for users to submit their information and messages.

The form should provide:

- Appropriate input fields.
- Required-field checks.
- Email input validation.
- Clear feedback when input is invalid.
- A submission response that informs the user of the outcome.

The form's actual email-delivery functionality must be verified separately. Client-side validation or a success message alone does not prove that an email has been delivered.

## 6. Enquiry Form Functionality

A separate `enquiry.html` page has been created to allow users to submit enquiries. Navigation links provide access to the enquiry page.

The enquiry form should include the necessary input controls, validation and clear submission feedback. The final implementation should be tested to confirm that the form processes the input and provides the expected response.
